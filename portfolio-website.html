Vibecoded Portfolio Site

Created and designed my portfolio website to showcase my services and expertise in user experience design and content writing. Explored development processes to improve future collaboration with devs. Used Microsoft Copilot and Google Gemini to assist with building the site.

Roles

Front-End Developer, Product Designer, and Content Writer

Scope

Personal Visual Identity, Content Strategy, Responsive Coding, WCAG Compliance

Duration and Tools

5 weeks

HTML, CSS, JavaScript, VS Code, Microsoft Copilot, Google Gemini, Git

Project Overview

I wore a lot of different hats while creating my new portfolio site from scratch. As the site's creator, I edited HTML files using Markdown and utilized Microsoft Copilot to assist with the style.css file. As the product designer, I created page content patterns and established a visual identity across the site. As the content writer, I filled in every single string and page with experiences showcasing my career. The end result is a scalable site that allows future flexibility as I continue to showcase the projects I work on throughout my career.

Background

I had previously created my portfolio website through Wix in 2024. However, Wix gave me limited autonomy over the structure of my project pages. This created unnecessary navigation steps and confusing page layouts, which lessened my credibility as a user experience designer and content designer. I figured that coding my own portfolio would allow me much more freedom to tailor my pages to my projects, creating a much better showcase of my abilities and skills.

Additionally, I have a limited background in web development and coding. I figured that this experiment with vibecoding would help me build prompt engineering skills crucial to any future career in tech. Further, iterating my prompts and seeing what Copilot generates in return will help me understand how to effectively articulate my design choices to others, in turn making me a better collaborator on teams with developers and other designers.

Process

I wore a lot of different hats throughout this project, each circle is a different hat. Click on the hat here to see the work associated with that role.

  1. 1

    Developer

    First, I consulted with Google Gemini to see what tools I would need to create a website on my home computer. I downloaded VS Code and Git to edit, preview, and save my code. I learned some basic Git commands, read up on prompt engineering, and began by using VS Code's built-in Microsoft Copilot to create the basic structure of the pages in my site.

    From here, Copilot was responsible for edits to the style.css file, and I was responsible for the edits to the Markdown files. Although I could have saved some time by using Copilot to edit all text, images, and elements, I wanted to develop an independent understanding of Markdown in the event that I work for a team with docs-as-code technical writing. AI is a great tool for closing knowledge gaps and increasing efficiency, but great AI usage requires an expert who understands the full context and evaluates AI generated content from their own point of view.

  2. 2

    Designer

    I began by conducting a competitor analysis of portfolios belonging to user-experience designers in the tech industry. I pulled portfolios from full-time, freelance, and entry-level designers and noted common trends in each portfolio. This process helped me choose ideas that would indicate my understanding of industry conventions while also showcasing my individual personality as a designer.

    After I selected the colors and fonts for the site, I used Google Gemini to create a style sheet detailing the use cases for the colors and typography. I would typically create a design system in Figma for larger projects, but this site was small enough that I felt like a general style sheet would suffice. After review and adjustment, I passed this style sheet along to Copilot to create the initial style.css file. I would continually adjust and rewrite the style sheet as I iterated designs through Copilot. After I settled on a consistent style, I created the finalized style sheet as depicted below, and used this style sheet to create the images for project cards.

  3. 3

    Content Writer

    Content informs structure, and structure informs content. While I was creating page layouts, I was simultaneously planning out the content I wanted to include in each case study. As I wrote out the case study content, I adapted the structure of the project page to highlight the key takeaways.

    The invisible writing for this project also included all of the prompts that created this site. While working with Copilot, I started to understand prompts as having two categories:

    • Divergent prompt: A prompt used to explore design possibilities. These prompts include open-ended language when describing the generation, but define the general outcome of the request.
    • Convergent prompt: A prompt used to create a specific and particular outcome. These prompts use technical language to actualize a pre-envisioned idea.

    Although “ensure mobile compatibility” seems akin to including “make no mistakes” at the end of a prompt, I felt that it was important to ensure that Copilot paid direct attention to mobile compatibility. The additional command to provide a mobile preview also helped me to review mobile compatibility as best as I could with the software I had. Each prompt ended with this request, and I often pulled from a library of repeated language to verify mobile compatibility, WCAG compliance, and performance.
